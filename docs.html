01 / Start here

What AppSweep is

AppSweep is an open-source Windows application manager built with Rust and egui. Its current goal is to help you discover installed software, inspect available metadata, and review related paths.

Platform

Windows 10/11

Project targeting is documented on the website; verify the latest repository notes for current requirements.

Maturity

Pre-alpha

Coverage, behavior, and packaging can change. Expect rough edges and verify results yourself.

Project status

Open source

Review the code, releases, and issue tracker through the official GitHub repository.

02 / Install

Find an official build

Use the project’s release pages rather than third-party mirrors. A source-code archive is not the same as a ready-to-run Windows application.

  1. Open the releases list.Check whether a release has actually been published and whether it includes a Windows package.
  2. Read the release notes.Review known limitations and any release-specific instructions before running the application.
  3. Check the downloaded file.Confirm that its name and source match the official release. Do not bypass Windows security warnings merely to make an experimental build run.

03 / Concepts

How to interpret results

AppSweep brings together information Windows and installed software make available. Availability and accuracy can vary by application and installation method.

Application discovery

The project currently describes discovery through Windows uninstall records, Store entries, and Start Menu shortcuts. These sources do not guarantee a complete inventory of every application.

Application details

Publisher, version, installation location, architecture, and uninstall information may be shown when those values are available. Missing details do not necessarily indicate a problem.

Related paths

A path associated with an application is only a lead to review. It may contain user data, shared files, or content still required by another program.

04 / Important

Safety before cleanup

Treat every result as informational until you have verified it independently.

  • Back up important files before testing experimental system utilities.
  • Verify the application name, publisher, and purpose of each reported item.
  • Do not delete a path just because AppSweep lists or associates it with an application.
  • Prefer the normal Windows uninstall process when removing software.
  • Do not rely on AppSweep for critical maintenance or assume that a result is complete or correct.
warning

A detected path is not proof that it is safe to delete. Removing the wrong files can break applications, remove personal data, or damage Windows components.

05 / Developers

Build from source

Build requirements and packaging can change during pre-alpha. Check the repository README and workflow files for the current toolchain and platform-specific prerequisites before compiling.

git clone https://github.com/PanDuroDev/appsweep.git
cd appsweep
cargo build --release

These are the basic Cargo commands, not a guarantee that every native dependency or runtime asset is packaged. If the build fails, capture the complete error and compare your environment with the latest repository instructions.

06 / Troubleshooting

When something does not work

No download is available

A release may not have been published yet, or it may not include a Windows package. Check the official GitHub Releases page and do not mistake source archives for application installers.

An application is missing or has incomplete details

Discovery depends on information exposed by Windows and the installation method. Record what you expected to see and what AppSweep actually showed; do not assume the inventory is exhaustive.

A build fails

Confirm that Rust/Cargo and the prerequisites documented by the repository are installed. Include the exact command and full error output when reporting the failure.

The site cannot load release information

The release list depends on GitHub availability and its API limits. Open the official Releases page directly and try again later if the embedded list fails.

07 / Community

Report a bug or ask for help

A useful report lets maintainers reproduce the problem without exposing private information.

  1. Describe the expected behavior.Explain what you were trying to do and what you thought should happen.
  2. Include reproducible details.Provide your Windows version, AppSweep release or commit, steps to reproduce, actual result, and relevant error output.
  3. Review the report for privacy.Remove usernames, personal file paths, tokens, and other sensitive data from logs or screenshots before posting.
