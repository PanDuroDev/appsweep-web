Getting started.

Find a build, compile from source, and understand the limits before testing AppSweep.

info

Experimental software. AppSweep is earlier than beta and is not a stable system-maintenance tool. Back up important data before testing.

01 / Downloads

Check for a published build

Open the AppSweep releases page to see every published version and its available downloads. The list updates from the official GitHub Releases API and may be empty until a release is published.

Read the release notes and requirements before running anything. Avoid unofficial download mirrors, and do not assume every source commit has a matching release binary.

02 / From source

Build on Windows

Native build requirements can change with the source. Review the current repository README and CI workflow before compiling. If the prerequisites are installed, start with:

git clone https://github.com/PanDuroDev/appsweep.git
cd appsweep
cargo build --release

A successful Cargo build does not guarantee native helpers or runtime dependencies are packaged. Follow the latest build instructions in the repository.

03 / Before you act

Verify every result

Application discovery, metadata, uninstall behavior, and path detection may be incomplete or inaccurate. Check the application, publisher, and purpose of each path.

A detected path is not proof that it is safe to delete. Removing the wrong item can break software or Windows components. Prefer the normal Windows uninstall flow when appropriate.

04 / Support

Report a problem

Include your Windows version, AppSweep version or commit, expected result, actual result, and relevant logs. Remove personal information and sensitive paths before posting.
